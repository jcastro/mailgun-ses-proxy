# 2.1.17: Next.js Security Dependency Update

This focused update moves Next.js from 16.3.4 to 16.4.4 and Sharp from 0.35.4 to 0.35.5. The bundled Vitest toolchain moves from 4.0.18 to the patched 4.1.12 backport, with a scoped override keeping Vite on the patched 7.3.7 release line rather than switching its major version. The lockfile includes matching Next.js environment/compiler packages and updated Sharp native binaries for supported platforms. The Docker build continues to use `npm ci` with this same lockfile.

## Security Scope

The updated versions address these reported critical advisories:

- [GHSA-vcvr-r3jv-pc5j](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j): Node.js `next/og` ImageResponse remote code execution; fixed in Next.js 16.3.6 and later.
- [GHSA-2464-fhr4-w9xw](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw): image optimization remote code execution with SVG input; fixed in Next.js 16.4.1 and Sharp 0.35.5.
- [GHSA-673q-mjm6-r5xr](https://github.com/vercel/next.js/security/advisories/GHSA-673q-mjm6-r5xr): Cache Components remote code execution for `use cache` functions returning multiple typed arrays; fixed in Next.js 16.4.1.

The proxy does not currently define `next/og` image generation or `use cache` functions, and its Docker runtime uses Alpine rather than glibc. This narrows exposure to the named exploit conditions; it is not a reason to ship known-vulnerable dependencies or a claim that the entire framework is unreachable.

Vitest 4.1.12 also resolves [GHSA-5xrq-8626-4rwp](https://github.com/vitest-dev/vitest/security/advisories/GHSA-5xrq-8626-4rwp), a critical advisory requiring an exposed Vitest UI/API server, and the `@vitest/mocker` advisories fixed by the 4.1.12 backport. Production starts the application server, not the Vitest UI/API server; no test service is enabled by this update.

New lockfile regression tests reject the affected Next.js, Sharp, Vitest, and mocker versions and require all Next.js compiler targets to match the framework version. CI additionally runs `npm audit --audit-level=critical` before tests/build/publication, including development dependencies because the current Docker image installs them too.

Other high/moderate dependency advisories remain and need separate investigation. This release deliberately does not upgrade Prisma, database drivers, Zod, or unrelated packages. A clean critical audit is not evidence of zero vulnerabilities or of no previous compromise.

## Deployment

1. Confirm there is no active newsletter and both sending/event queues have no visible, invisible, or delayed backlog. Verify the proxy/database health and retain a recent database/configuration recovery point.
2. Pull `ghcr.io/jcastro/mailgun-ses-proxy:v2.1.17`, verify its digest and dependency versions, and retain the prior image for rollback.
3. Recreate only the proxy service using the existing Compose deployment procedure. No migrations, queue resets, campaign edits, suppression changes, or Ghost/Discourse upgrades are required.
4. Verify the running image/version, healthcheck, authenticated event/statistics reads, unauthenticated API rejection, SES account health, empty queues, unchanged schema/configuration, and recent logs. Check Ghost, its admin UI, and Discourse still return HTTPS 200.
5. If validation fails, restore the prior Compose image pin and recreate only the proxy. Do not resend an existing campaign to test the upgrade.

The 2.1.16 reserved-header filter, unsubscribe headers, per-recipient idempotency, event processing, suppression behavior, and send-rate settings are preserved.
